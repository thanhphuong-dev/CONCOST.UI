# Changelog

All notable changes to CONCOST.UI are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **The collapse ladder has a rung between "small" and "give up a panel".** Demoting `Large` → `Medium` → `Small` was the whole ladder, so the step after three rows of small buttons was to fold a panel — surrendering a set of commands to buy back forty pixels. The captions of the small buttons now go first (`Ribbon.ShowGroupLabels` / `ShowItemLabels`, both inherited, so one value on the ribbon reaches every item; `RibbonItem.IsLabelVisible` reports the result), which is the cheapest width a group can hand back without losing a command — only the words go. `RibbonItem.CollapsePriority = 0` pins a command at its own size the way `RibbonGroup.CollapsePriority = 0` pins a panel. Restoring the captions also moved out of `RestoreAutoCollapsed` and into the branch that has actually measured the full layout as fitting: with both sides restoring, the rung and the width restore undid each other every other pass and the ladder could never settle on a fold — which is why `RibbonExtendedPropertiesTests` now hosts its three groups at 240 px, narrow enough that folding one is still the only way to fit.
- **The ribbon family reads its own theme tokens instead of borrowed ones.** A `RibbonToggleButton` was drawn from the generic `CONCOST.Brush.Accent` / `Border` pair, so a ticked command in a checked tab read as two different accents on the same row, and `RibbonButton`/`RibbonGroup`/the tab strip each picked a different grey for hover. Item hover, pressed, checked and disabled now come from `Ribbon.ItemHover`, `ItemPressed`, `ItemChecked`, `ItemDisabledForeground` and their border pairs, the strip from `Ribbon.TabStrip` / `TabSelected` / `ContextualAccent` / `Divider`, and the panel title has its own height token (`CONCOST.Ribbon.PanelTitleHeight`, 18 px — the row that has to hold both the slide-out toggle and the dialog launcher). A fold state that hides a caption now also zeroes the icon's margin, so an icon-only tile sits centred instead of hanging to the left.
- **`ViewCube` is the Revit-style widget of the specification, and the maths left the control.** The old cube offered three faces, twelve edges named after their corners and a dotted compass, read a `ViewDirection` vector, and handed the host a `Hit` carrying a direction and a count of quarter turns — an absolute orientation the host still had to translate into whatever its camera spoke. The cube is now a bevelled solid with **26 hit regions** — six captioned faces, twelve edge strips, eight corner triangles — and the whole geometry lives in `ViewCubeMath`: the region table with its face/edge/corner normals and uprights, `RotationFor`, basis conversion, `Roll`, short-arc `Slerp` and the `Upright` projection behind `KeepSceneUpright`. The control reaches a camera through `ICameraHost` (`Rotation`, `PivotPoint`, `Projection`, `FitToView`), so `CameraController` speaks quaternions and a host that works in directions converts at its own boundary; `ICameraHostEvents` is the optional half that tells the cube the user orbited, and `Invalidate()` is there for a camera that cannot. Around the cube: a compass ring on the ground plane whose letters drag the yaw (hidden below ten degrees of elevation, where it collapses to a line), a home button, four 90° chevrons and two roll buttons that appear only when square on a face, and a context menu with the three projections, Set Current View as Home and as Front, Reset Front, Show Compass and Options. The specification's options table is dependency properties — `Position`, `DockMargin`, `Size` (Automatic is a fifth of the short side clamped to 64-160 px), `InactiveOpacity`, `SnapToClosestView`, `SnapAngle`, `FitToViewOnChange`, `AnimatedTransitions`, `AnimationDuration`, `KeepSceneUpright`, `ClickThreshold`. A press under the threshold turns the view, a longer one orbits and snaps within `SnapAngle`, a transition is a 200-600 ms `slerp` that continues from the pose on screen when interrupted, and the transparent parts of the widget pass the click through to the viewport. The 33 new tests in `CadViewTests` cover the 26 regions, the `u = (ẑ − (ẑ·f)f)` upright of the edges and corners, the short arc, the roll sense, and a hit test at the centre of every one of the 26 zones.
- **The drawing surface stopped looking like graph paper.** `ViewportControl` borrowed `CONCOST.Brush.Border` for its minor grid and `BorderHover` - three times darker - for every fifth line, and painted the two world axes in the accent colour, so a plan sat under a dense grey mesh crossed by two orange lines that read as warnings. The grid now has its own pair of theme brushes (`CONCOST.Brush.CanvasGrid`, `CanvasGridMajor`, `CanvasAxis` in both `Light.xaml` and `Dark.xaml`), the axes are a dashed neutral datum, and the three pens are built once per frame instead of allocating one per line - several thousand objects on every camera move.
- **The two lines through the middle of a `ViewportControl` are a layer of their own, not part of the grid.** They are the model's X and Y axes through the origin, and a host had no way to say so: `ShowAxes` was the only switch, the brush and the dash were fixed, and `ShowOriginMarker` lived inside the same pass, so turning the axes off took the origin ring with it. The datum is now its own pass with its own properties, the ring stands alone, and the grid weight test moved into `WeightPen` so nothing but a grid line can ever be drawn heavier. The snap caption (`GRID`, `ENDPOINT` — the snap kind in capitals) and the aperture are switchable too, and `SelectionFillOpacity = 0` draws the pick box as an outline rather than tinting the geometry the user is trying to read under it.
- **A dimension string no longer draws its ticks on top of each other.** Two wall lines a few centimetres apart produced two slashes a few pixels apart in the middle of the string; a tick now yields to the one before it when it would land within six pixels.
- **The properties palette's title and subtitle have a pixel of air between them.** At eleven pixels the subtitle sat on the descenders of the title and the pair read as one smudged line.
- **Trees no longer hang a dashed line under every branch.** The base `TreeViewItem` template drew a one-pixel `2,2` guide line down the whole of every expanded item, which at that weight reads as a rendering artefact rather than as a guide — and it dangled below the last node of a short tree. The default template draws no guide lines now; the `CONCOST.TreeView.Line` style keeps them for a host that wants a directory listing.
- **The properties palette has an empty state, one search box and no decoration.** With nothing selected it showed a search-and-sort card above a few hundred pixels of white, and it stacked that card over the palette's own search field. The card is gone (`ShowToolbar="False"`), the panel shows a centred hint instead, and the grid no longer draws its own border inside the palette's.
- **The command line reads as a band, not a form.** Its input was a full-width boxed `TextBox` under a fixed 104 px container, so the control was mostly empty space with a rounded rectangle in it. The input is now an underline (`CONCOST.TextBox.Underline`), the control sizes to its feed plus its input row, and the Revit-Like shell separates the band with a rule.
- **A project browser puts its search and its kind filter on one row.** Three stacked full-width bars pushed the tree itself below the fold of a 290 px palette; the filter is a short list and belongs beside the search.
- **`ViewControlBar` no longer paints its hide/isolate button in the accent colour.** `CONCOST.SplitButton.Small` inherits the accent fill, and a permanently orange button at the bottom of a drawing competes with the selection it is supposed to act on.
- **Ribbon captions wrap instead of being cut.** A large item owns one 70 px column, and its caption was a single trimmed line, so `Command Line` and `Structural Wall` arrived on the ribbon as `Command…` and `Structural…`. The caption now wraps with a two-line cap — the same trade Office and Revit make in the same column — and the sample's remaining long labels moved into screen tips.
- **The Showcase catalog no longer has a 75-page "Custom Controls" bucket.** The sidebar always offered six buckets, but 75 of the 144 pages were registered under the seventh, which mixed effects, inputs and layout panels together and made unrelated pages look like duplicates of each other. Every page was moved to the bucket it belongs to:
  - **Effects** (6 → 31): the animation and decoration controls, from `AuroraBackground` and `ConfettiBurst` to `TiltCard`, `ParticleField`, `TypewriterText` and `Reduced motion`.
  - **Layout & Shell** (9 → 24): `Ribbon`, `Drawer`, `DrawerMenu`, `SideMenu`, `Dialog`, `Growl`, `Breadcrumb`, `StepBar`, `Pagination`, `AvatarStack`, `PageTransitionHost`, `Skeleton`, `LoadingOverlay`.
  - **Input & Drag** (5 → 16): `SearchBox`, `NumericUpDown`, `ColorPicker`, `Rating`, `CheckComboBox`, `PinBox`, `RangeSlider`, `AutoCompleteTextBox`, `FilePicker`, `CalendarWithClock`, `DragDropHelper`.
  - **Data Controls** (5 → 14): `Charts Suite`, `StatisticCard`, `Transfer`, `Timeline`, `Sparkline`, `RadialGauge`, `HeatmapCalendar`, `OdometerNumber`, `StackedHeaderDataGrid`.
  - **Basic Controls** (27 → 32): `Tag / Chip`, `Divider`, `Clock`, `Icons Gallery`, `ThemePreset.Brutal`.
  - **Custom Controls** (75 → 10) keeps only the purpose-built composites: `PropertyGrid`, `Spreadsheet`, `CommandPalette`, `Ribbon`, `Magnifier`, `CompareSlider`, `ImageViewer`, `MarkdownViewer`, `MiniMap`, `ModelViewer3D`.
  - The Documentation page's category table was rebuilt from the same eight buckets, so the guide and the catalog can no longer disagree, and the Overview's *Interactive components* tile now counts every demo page instead of only the two buckets that have a card.
- **`net10.0-windows` is only targeted when the SDK can actually build it.** The target was listed unconditionally, so on SDK 8 or 9 restore failed with `NETSDK1045` for the whole project — including the two targets the machine did support, which made the library unbuildable everywhere but a .NET 10 preview install. The third target is now appended only when `NETCoreSdkVersion` is 10 or newer, `TargetFrameworks` stays `net48;net8.0-windows` elsewhere, and CI installs both SDKs instead of 8 alone.
- **`DockingManager` now follows the AvalonDock model.** The first version treated the four edges as four slots and stacked every panel docked to one edge, each with its own slice. That is not how an IDE behaves, so the layout was rebuilt around **pane groups**:
  - **Tabs.** Panels docked to the same edge form one group and show as tabs along that edge (bottom for side and bottom edges, top for the document area). The selected tab is `ToolWindow.IsActive`, and a pane's own header hides while it has siblings, because the tab already names it. Setting `IsActive` from code switches the tab exactly like a click: the manager listens to `ToolWindow.Activated` and clears the rest of the group.
  - **Proportional sizing.** A pane keeps its share of the window when the window is resized, the way a `GridLength` star column does, instead of staying at a fixed pixel width. `IsProportional = false` pins it back to pixels. The scale factor is applied in measure and the accounted-for size is recorded there, so the second pass does not scale again and the panes cannot run away.
  - **Five drop zones.** A drag now resolves the edge from the **pane under the pointer** (25% bands on each side, the rest is the centre) instead of four global bands on the manager, and the dashed hint draws the region the pane will actually occupy after the drop.
  - **Layout persistence.** `CaptureLayout()` / `ApplyLayout(string)` round-trip each pane's edge, size, auto-hide state and selected tab through a small versioned text format (`CONCOST-DOCK-1`). Panes are matched by `Header`, so an unknown pane in an old snapshot is skipped rather than corrupting the layout.
  - `Group(DockSide)` exposes the panes sharing an edge; `DockTabStrip` is the tab strip control and is public, so a custom layout can use it.
- **`NavigationBar` drew three outlines around nothing.** The bar's own frame was a 1 px `CONCOST.Brush.Border` plate with a shadow, and every command inside it was a `CONCOST.Button.Icon` chip — `SurfaceSecondary` fill, an outline of its own, a 34 px minimum — so a row of outlined boxes sat inside an outlined plate and read as a table of cells rather than as one tool. On the Showcase page the demo's wrapper added a third. The commands are now flat (`CONCOST.Button.Icon.Ghost`, `CONCOST.ToggleButton.Icon.Ghost`) and only fill in on hover, the coordinate-system label is a text button with a caret instead of a boxed one, and the frame is the only thing with an edge. That 34 px minimum was also coercing `ButtonSize`, so a bar asking for 26 px buttons rendered 34 px ones; the bar now zeroes it. The rules between groups were `Brushes.LightGray` at 60 %, which is a bright line on a dark theme, and now take `CONCOST.Brush.Border`. A hidden group also takes the rule beside it, so no line is left floating at the end of the bar.
- **`ViewControlBar` drew four outlines and stood a third taller than it claimed.** The bar had a `Surface` plate with a 1 px border, every toggle inside it was a `CONCOST.ToggleButton.Icon` chip with an outline of its own and a 34 px floor, the hide/isolate split button brought a third, and the Showcase's demo wrapper a fourth — the same table-of-cells look the navigation bar had. Only the frame carries an edge now: the toggles and the hide button use the ghost styles, so they stay flat until hovered and fill with the accent only when ticked. The height was the bigger lie. The combo style sets `MinHeight = 34`, so a bar that asked for 26 px pickers rendered 34 px ones and dragged the whole plate with it; `ControlHeight` zeroes each minimum before setting the height, and the icon toggles get the same treatment against their own 34 px. The rules between groups were `Brushes.LightGray` at 60 %, which is a bright line on a dark theme, and are now `CONCOST.Brush.Border`; a rule beside a group that has been switched off steps aside with it. The hide caption was the hard-coded English `Hide` and is now `HideIsolateCaption`.
- **The command line logged the answer without the question.** A prompt put its text in the input row alone, so answering `Specify next point` wrote `1200,400` into the feed as a bare number with no question above it — the history read as a list of outputs rather than as a conversation. `BeginPrompt` now writes the question into the feed and `AnswerPrompt` joins the answer onto that same line (`Specify next point: 1200,400`), recoloured to `TextSecondary` so question and reply read as one entry. The Showcase page also stopped seeding the feed with two `WriteLine` instruction lines: a history that opens with help text is a caption pretending to be a transcript, and it was the first thing anyone saw on the page.
- **The dynamic input drew two outlines around one number, and glued the unit onto the question.** `DynamicInput` was a rounded 1 px frame holding a stock `TextBox` with a border of its own, so a value read as a form inside a form on top of the drawing; the prompt appended `"  (mm)"` to whatever text the host had set, so a translated question — `Chiều dài  (mm)` — arrived as one run-on string the host could not reorder; and the digits were proportional, so a stack of boxes never lined up. The plate is now the only outline, the field is a `CONCOST.TextBox.Underline` (a 1.5 px rule that takes the focus colour by itself), the unit is a separate block at the end of the question row that `Kind` fills in and `UnitSuffix` overrides, and the value is set in Consolas so `3200` and `(mm)` sit still while the user types. A value that will not parse paints that same outline in `CONCOST.Brush.Danger` and puts the reason under the row. The Showcase page was rebuilt around a live chain: pick a start point and each typed length draws the next segment, so the typed number and `Undo` / `Esc` have a visible consequence instead of a static box on a grey plate.
- **`CadStatusBar` read as a row of orange blocks inside a frame.** The five snap switches were `CONCOST.ToggleButton.Icon` chips — a 34 px minimum that beat the bar's own 24 px height, so each switch stood a third taller than the plate and dragged the plate up with it — and every one that was on filled with the solid accent, so a drawing with SNAP, GRID and ORTHO enabled showed three orange squares where the user expects a status, not three alarms. Nothing said which switch was which: no caption anywhere in the bar. The work-plane button was an accent pill nobody had picked, the task and notification counters were grey `Secondary` capsules that read as a second kind of button, and the Showcase wrapped the whole thing in its own `Border`, so the page displayed a plate inside a plate. The bar now draws exactly one outline and the switches print straight onto it, flat until hovered: `CONCOST.ToggleButton.Status` carries the glyph and the caption on one row, `CONCOST.Button.Status` dresses the two counters in the same clothes, and both inherit the bar's foreground, font and size instead of bringing their own. The on state is `PrimarySoft` at 12 % with the accent left to the glyph and the text, which is what stops five permanent switches from reading as five warnings. `ControlHeight` zeroes both minimums before it sets a height, the work plane became a `CONCOST.SplitButton.Ghost`, the rules between groups take `CONCOST.Brush.Border` and step aside with a group that has been switched off, and the demo stopped wrapping what it had already been given.
- **The project browser page showed the control twice.** The Showcase put a second search `TextBox` above the browser and two more pickers under the tree, so the page carried two search boxes, two sort pickers and two kind filters within a few pixels of each other — the control already owns all three, and a host that adds its own is not extending the browser, it is doubling it. Inside the control the tools were four 26 px `CONCOST.Button.Icon` chips sitting beside a `CONCOST.ComboBox.Base` picker whose `MinHeight = 34` beat the 26 px it had been given, so a row of outlined boxes and one taller dropdown stood under a search field, and the whole thing was staged the full width of the page, where a tree of six rows is a corner of white in a very large rectangle. Every caption — `All kinds`, `Name A–Z`, `Search the project` — was a hard-coded English literal, so a Vietnamese shell had no way to translate the one part of the palette the user reads most. The header is now two rows and nothing else: the search and the kind picker share the first, three ghost chevron tools stand flat until hovered beside the group switch and the sort picker on the second, a rule in `CONCOST.Brush.Border` separates them from the tree and a matching rule carries the item count at the foot. `ControlHeight` zeroes the search box's and both pickers' minimums before it sets 24 px, so no part of the palette is taller than the plate's own rows, and the node glyphs were redrawn for 13 px — the filled isometric solid and the solid folder read as dark squares in a tree of outlines.

### Added
- **The ribbon folds like Office, not like a switch.** `IsMinimized` only ever knew two states, so "minimised" meant the body disappeared and came back whole. The ribbon now has `DisplayMode` with the four states the specification names — `Full`, `MinimizeToTabs`, `MinimizeToPanelTitles`, `MinimizeToPanelButtons` — and `CycleState()` walks them in that order, driven by a caret at the right end of the tab strip and by a double-click on a tab. In `MinimizeToTabs` clicking a tab raises the body as an **overlay** under the strip instead of growing the header again: the content host is reparented into the popup's shell (`IsOverlayOpen`), the row holding it collapses to **zero height** rather than `Visibility.Collapsed` — a collapsed element cannot be unhidden from inside a popup, and the overlay borrows that very element — and the overlay closes after a command runs or a click lands outside. `IsMinimized` is kept as a shim and stays in step in both directions, so a host written against the old flag keeps working. `RibbonGroup.IsTitleOnly` / `IsButtonOnly` are what the last two states set, so a host can produce the same look by hand. `ShowMinimizeButton` and `ShowInfoCenter` switch off the chrome, and `InfoCenter` is a content slot at the strip's right end for account, sync state or a build badge.
- **Contextual tabs got an API.** `RibbonTabItem.ContextualGroup` styled a tab as contextual, but nothing turned one on and off with the selection. `ShowContextualTab(tab, activate = true)` appends it, selects it unless told not to, and refuses to add the same instance twice; `HideContextualTab(id)` removes it and restores whichever tab was open before — the two calls a wall-selection handler actually needs.
- **`RibbonLabel` and `RibbonRadioGroup` — the two item types a folding ribbon needs.** A panel that has shrunk to small tiles needs a line of static text beside a cluster of controls, and `RibbonLabel` is that line: no focus, no tab stop, hit-test transparent, one row, centred. `RibbonRadioGroup` holds `RibbonRadioButton`s and keeps **exactly one** ticked — `SelectedIndex` / `SelectedItem` both ways, a member ticked by the user is followed rather than fought, and the last member cannot be unticked, because a mutually exclusive set with nothing selected is not a state the user can have meant. It draws no caption of its own: at a 74 px group height a caption plus three 24 px rows would overflow.
- **`RibbonGroup.SlideOut` — a real expanding panel, not a rebuilt menu.** The group flyout re-creates the items as a menu, which is the only thing a WPF control can do when it has a single visual parent; the slide-out is the other half of that answer. Assign anything to `SlideOut` (plus `SlideOutTemplate`) and the header grows a toggle beside the dialog launcher that opens it in a popup, two-way bound to `IsSlideOutOpen`, with `HasSlideOut` following the content. Content you already own keeps its own layout and its own state, because nothing is rebuilt.
- **Two-level tooltips, and they append rather than replace.** `RibbonToolTip` carried a title, a description, a gesture, a preview and a footer, all of which appeared at once — there was no short form and no long form. `ExpandedDescription` adds the rest of the story after `ExpandDelay` (1500 ms by default) once `CanExpand` says there is something to tell, and the long half is **appended** under the short text instead of swapped in, so a tip that carries only a preview, or only a footer, still shows its description. `Footer` now takes part in `CanExpand` too — a footer-only tip could never expand before. `RibbonItem.ExtendedScreenTip`, `ToolTipPreview` and `ToolTipFooter` write that content straight onto the item, which builds the `RibbonToolTip` for you.
- **`RibbonSplitButton.RememberLast`.** The left half of a split button runs its own command, which is right for `Bold` and wrong for `Save`: Office relabels the left half to whatever was picked last and replays it. `RememberLast` opts in, `LastUsedItem` reports the pick, and `BodyHeader` / `BodyIcon` follow it — so a custom template shows the same caption the shell does.
- 16 tests in `RibbonDisplayModeTests` cover the four states and the shim in both directions, the per-state panel look, the overlay closing itself, both contextual-tab calls including the tab left alone by `activate: false`, the radio group's refusal to empty itself, the label's inertness, the split button with and without `RememberLast`, the caption rung, a pinned item keeping its tile, and both halves of the tooltip rule. The suite was **628** at that point, with 0 warnings and 0 errors on `net48` and `net8.0-windows`.
- **`ViewportControl` chrome - eighteen properties, one per colour and one per switch.** The surface could paint five layers but only decide whether each one existed: the datum, the grid weights, the aperture, the snap glyph and the dimension all shared the accent colour, and the pick box filled whether or not the user needed to read the geometry underneath it. `ShowAxes`, `AxisBrush`, `AxisThickness`, `AxisDashStyle` and `ShowOriginMarker` dress the datum, `GridBrush` / `GridMajorBrush` / `GridMajorEvery` / `MinGridPixelSpacing` the grid, `CrosshairBrush` and `ShowAperture` the cursor, `SnapMarkerBrush` / `SnapMarkerSize` / `ShowSnapLabel` the snap, `SelectionBrush` / `SelectionFillOpacity` the rubber band and `DimensionBrush` the temporary dimension; `FitMargin` is the air `ZoomToFit` leaves around the bounds (clamped to ≥ 1, so a drawing is never cropped). Every brush defaults to `null`, which means *keep the theme token*, so a host can retune one layer and still let a theme switch repaint the rest - and `SetResourceReference` on any of them keeps an override in step with the theme as well. The Showcase's *Trục toạ độ và từng lớp màu* section wires all of them to live controls. 14 tests in `ViewportChromeTests` paint the surface into a `RenderTargetBitmap` and sample the pixels: the datum at the projected origin and nowhere else, the grid surviving the datum's absence, minor and major brushes on the right lines, the pixel-spacing ladder thinning a dense grid, the pick box as an outline at opacity 0 and as a fill at 0.6, the snap caption removable without losing the marker, the marker growing with its size, and the fit margin clamped. The suite is now **642**, with 0 warnings and 0 errors on `net48` and `net8.0-windows`.
- **`NavigationBar` is one attribute away from wherever it sits.** Nine new dependency properties: `Variant` — `Floating` over a viewport, `Seamless` inside a toolbar (no fill, no outline, no shadow), `Glass` (a 90 % plate with a shadow, for a busy 3D scene) — `Orientation`, which turns the row into a column and the rules with it, `ButtonSize` (26 px by default, 34 for a touch target), `IconSize`, `CornerRadius`, `Elevation` (0-4, ignored by `Seamless`), and `ShowUcsLabel` / `ShowZoom` / `ShowPerspective` / `ShowDividers` for the groups, joining the `ShowWalk` that was already there. `CONCOST.Button.NavigationLabel` is the new text-button style the label uses. The Showcase page stages the bar over a dark gradient with a `Kiểu` and a `Hướng` picker, five group switches and four size sliders, plus a second section showing the same bar docked in a toolbar with `Variant="Seamless"`. 12 tests in `NavigationBarChromeTests` paint the bar and read the pixels back — the floating frame inks the length of its top edge, the seamless one inks nothing — and cover the variant round trip, the elevation and radius reaching the frame, `ButtonSize = 30` surviving the ghost style's minimum, the column layout, and each group taking its rule with it. `ThemeDictionary_ContainsTheStyleKeys` now names the three styles the bar relies on, so a rename fails the suite instead of quietly handing its commands back to the stock outlined button. The suite is now **657**, with 0 warnings and 0 errors on `net48` and `net8.0-windows`.
- **`ViewControlBar` is one attribute away from wherever it sits.** `Variant` — `Floating` over a viewport (one outline and a shadow), `Seamless` inside a status bar (no fill, no border, no shadow), `Glass` (a 90 % plate that keeps a shadow, so a busy drawing still reads through it) — plus `CornerRadius`, `Elevation` (0–4, ignored by `Seamless`), `ControlHeight` (one height for every picker, toggle and button on the bar, 20 px and up), `IconSize`, `ShowDividers` and one switch per group: `ShowScale`, `ShowDetailLevel`, `ShowVisualStyle`, `ShowToggles`, `ShowHideIsolate`. `Scales` takes the host's own list — `null` means the five a plan is normally read at — and it accepts an `ObservableCollection`, so a scale the user adds appears in the dropdown without the bar being rebuilt; a `ViewScale` that is not in the list is appended rather than showing a blank box, which is what a restored view needs. The Showcase page stages the bar on a light gradient drawing sheet, adds a `Kiểu` picker, seven group switches, four sliders for height / icon / radius / elevation and an *add a scale* row that grows the live list, plus a second section showing the same bar with `Variant="Seamless"` docked in a status bar. 17 tests in `ViewControlBarChromeTests` paint the bar and read the pixels back — the floating frame inks the length of its top edge, the seamless one inks nothing — and cover the variant round trip, the elevation and radius reaching the frame, `ControlHeight = 30` beating the combo's 34 px minimum on the pickers *and* the toggles, `IconSize` reaching every glyph, each group taking its rule with it, the translatable caption, and the scale list refilling from an observable collection and from a scale it never listed. `CONCOST.SplitButton.Ghost` gained `BorderThickness = 0`: a transparent border is still a border, and it still counted as one when the test measured the bar. The suite is now **675**, with 0 warnings and 0 errors on `net48` and `net8.0-windows`.
- **`CommandLine` speaks the CAD dialect.** A keyword set is now part of the prompt instead of something the host had to parse back out of `e.Text`: `CommandDefinition.WithOptions("Undo", "Close")` renders `Specify next point or [Undo/Close]:`, `MatchOption` resolves `U` and `C` by the capital letters the brackets advertise (and answers nothing when a prefix fits two keywords, because a guess runs the wrong command), and `PromptCompleted` carries the chosen keyword in `e.Option` — `null` when the answer was a value. `SpaceSubmits` makes the space bar run the command like Enter when the caret is at the end, since a CAD command is one word and one keystroke. `CommandLineVariant` places the bar: `Inline` (no surface, for a card), `Docked` (one rule along the top, the other three sides being the window frame) and `Floating` (a rounded plate whose shadow follows `Elevation`, with `CornerRadius`). `F2` / `ToggleHistory` expand the feed to `ExpandedHistoryHeight` and back to `HistoryHeight`, and `ShowHistory = false` leaves the single input row a folded AutoCAD command line shows. `EchoPrompt` turns the transcript echo off for a host that logs its own. ### Removed

### Fixed
- **`Card` drew its shadow twice.** The style set `UIElement.Effect` and the template's root `Border` bound the same value, so every card carried two `DropShadowEffect`s — twice the blur for twice the cost, and the second one ignored the theme. The template no longer binds it; `Card.Elevation` drives the appearance pack, which owns the effect.
- **`Card.Footer` was never rendered.** The footer border sat in the template with `Visibility="Collapsed"` and no trigger to bring it back, so the property existed, bound, and produced nothing. It is visible by default and collapses only when `Footer` is null (`Card_Footer_AppearsOnlyWhenThereIsOne`).
- **`PropertyGrid` wiped the categories its host had just filled.** The first layout pass applies the template, and `OnApplyTemplate` rebuilt the collection from `SelectedObject` unconditionally — so a palette that filled `Categories` itself and only became visible at the moment of a selection lost every row, and the panel read *"10 parameters."* above nothing. The rebuild now only runs when there is a `SelectedObject` to reflect over (`PropertyGridTests`).
- **`ViewportControl.ZoomToFit` framed the sphere around the bounds in an orthographic view.** `CameraController.FitTo` sizes the view from the bounds' 3D diagonal, which is right for perspective and wasteful in plan: a 24 m × 16 m floor landed at two thirds of the pane, with the drawing as a postage stamp in the middle. An orthographic camera is now framed against the bounds projected onto its own screen axes, honouring the pane's aspect ratio (`WorkspaceActivationTests`).
- **`DocumentWorkspace.AddDocument` never raised `ActiveDocumentChanged`.** The overloads assigned the backing field and rebuilt the tabs themselves, so a host that opened a view by adding one kept the previous view's document title and status bar — the title stayed on the project name and a 3D view still reported the top work plane. Both overloads now activate through the `ActiveDocument` property.
- **`ProjectBrowser.ExpandAll` left the tree scrolled to the bottom.** Item containers are generated as they come into view, so a full expand ended up showing the last branch and hiding the root node. `ExpandAll` now scrolls back to the first node, and `ScrollToTop()` is public for a host that rebuilds the tree itself.
- **`DockingManager.Float` crashed the app when called twice on the same panel.** The first call reparented the panel into a `Border` inside its window; the second call only removed it from `Children` — where it no longer was — and then set `Border.Child`, so WPF threw *"Specified element is already the logical child of another element"* and the process died. `Float` is now idempotent: it keeps a panel→window map and brings the existing window forward. `Detach` takes a panel out of whatever holds it (a group, the manager, a floating host), and `Dock` closes the floating window first for the same reason.
- A `DockPaneGroup` in tabs mode ping-ponged between two layout passes for ever: `ComputeRects` collapsed the inactive tab while `ArrangeOverride` forced every child back to `Visible`, so each pass undid the other and the process died with a stack overflow. Visibility is now owned by the measure pass alone.
- **`DockingManager` splitter bands were not hit-testable.** A `Panel` paints nothing, so the 6px band between two panes was empty space: mouse events passed through to whatever was behind, the resize cursor never appeared and dragging a splitter did nothing. `HitTestCore` now claims the bands (and only the bands), and `OnRender` draws a hairline in each one — which also makes the divider visible for the first time. `SplitterBrush` overrides the colour; empty takes `CONCOST.Brush.Border`.
- **Drag-to-redock never started.** `ToolWindow` captured the mouse on itself but subscribed `MouseMove` / `MouseLeftButtonUp` on the header bar. Once an element captures, the mouse route begins at the capture element and bubbles up, so a handler on a *child* of the capture element stops running — the drag never passed its 4px threshold and `DragStarted` was never raised. The move and release handlers now sit on the `ToolWindow`, and a `LostMouseCapture` handler clears the flag so a cancelled drag cannot stick.
- **The auto-hide flyout was painted under the centre pane.** Child order is z-order in a `Panel`, and the flyout kept its declaration position, so the document area drew over it and opening a flyout looked like nothing happened. `ToggleFlyout` now moves the pane to the top of the child list, then puts the drop preview back above it.
- `ToolWindow.IsActive` was never set, so the active-panel header highlight could not appear; the manager now marks the panel under the click and clears the others.
- `ToolWindow` drew the pane's **body** in its header bar instead of `Header`, so every tool window showed an icon and a clipped copy of its content.
- The pin and close buttons in the `ToolWindow` header, the close button on a `DocumentTabItem` and the buttons in `QuickAccessToolbar` rendered nothing: they used an icon-only button style whose template reads the attached `IconElement.Kind`, while the icon was passed as content. They now set `IconElement.Kind`, which is what that style actually draws.
- The `CommandBar` and `QuickAccessToolbar` overflow chevrons were `ToggleButton`s wearing a `Button` style — a target-type mismatch that threw while the template was being applied. They now use the `ToggleButton` ghost style.
- The `TreeDataGrid` expander rendered as a solid accent block with an invisible chevron; it now draws a 10px chevron in the secondary text colour, down when a branch is open and right when it is closed.
- `SnowCanvas_RendersAfterLayout` asserted a painted fraction tight enough to fail on an unlucky seed (0.18% against a 0.20% floor). Flake positions are random, so the floor is now 0.10% — the test is asking "did the template paint anything", not "how much".
- **`ViewControlBar.SettingsChanged` only fired for the pointer.** The event was raised from the click handlers, so a host restoring a saved view by setting `ViewScale` / `DetailLevel` / `VisualStyle` / `ShowShadows` / `CropView` / `RevealHidden` from code was never told, and AC-013 held only as long as the user did the clicking. It is now raised from `OnPropertyChanged` with the property name, guarded against the internal sync pass so one click is still one event.
- **`ApplicationInfoBar` could keep a transparent background for ever.** The tint was read from the theme dictionary when the severity was applied, which is before the host has necessarily merged that dictionary — a bar built in a view model constructor stayed blank after being parented. Resolution now happens on the first measure pass, where parent and dictionary are both guaranteed, and is re-armed on `OnVisualParentChanged` so a bar moved into another theme picks up the new tint.
- **`CodeEditor.FindNext` warned on `net48`.** `string.IsNullOrEmpty(term)` narrows nothing under the .NET Framework reference assemblies, which carry no nullable annotations, so `term.Length` on the next line was a `CS8602`; the check now tests `term` directly.

The next theme change then died with “Cannot set a property on object '#FF0F172A' because it is in a read-only state”. Only the glyph geometries are frozen now, so the shared ink brush stays live and the icons follow the theme.
- Switching away from the `Brutal` preset pinned `CONCOST.Brush.Background`, `Surface`, `Border` and the text brushes in the application's own resource dictionary. `ResourceDictionary.Contains` also looks inside merged dictionaries, so the "original" value saved before Brutal was the light theme's brush, and restoring it wrote that value back at application level — after which Light/Dark could no longer change those brushes. The snapshot now only records keys the application really owns, and anything else is removed so the theme dictionary shows through again.
- The quick-access toolbar drew its customise chevron even with nothing pinned, leaving a lone triangle floating in the tab row. It is now collapsed while the toolbar is empty.
- Gallery tiles clipped their captions and left uneven rows: the cell was sized for the swatch while the template drew swatch + label. Tiles are now uniform at any ribbon width.

## [1.0.1] - 2026-10-30

### Fixed
- The Showcase app icon rendered as a blank square in Explorer and was missing in the header. The .ico stored only PNG payloads; Windows needs DIB (BMP) frames for 16-128 px and reserves PNG for 256. The packer now emits real DIB frames, and the in-app logo uses a PNG so it never depends on frame selection.
- Replay buttons did nothing: `AnimatedEffectBase` kept accumulating elapsed time, so toggling `IsAnimated` re-hooked the loop but the effect stayed finished. Added `Restart()` (plus `OnRestarted()` for derived phase state); the TypewriterText and TextReveal demos use it.

### Added
